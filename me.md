Absolutely. If you're building a **game concept/design package**, there are many different sheets, documents, diagrams, graphs, maps, and matrices you can use. There isn't one mandatory set, but here's a comprehensive taxonomy.

 ## 1\. Game concept & vision

 These define **what the game is**.

 - **Game Concept Document (GCD)** — one-page/high-level description of the game.
- **Game Vision Document** — the overall creative vision and goals.
- **Game Pillars** — 3–5 principles that define what the game should feel like.
- **Elevator Pitch** — the game explained in a few sentences.
- **Game Overview** — genre, platform, audience, setting, premise, USP.
- **Feature List** — major systems and features.
- **Design Goals** — what the game is trying to achieve.
- **Non-Goals** — things deliberately outside the game's scope.
- **Player Fantasy** — what the player is supposed to feel like they are/do.
- **USP / Differentiators Sheet** — what makes the game different from competitors.
- **Reference Board / Mood Board** — visual references for art, tone, architecture, characters, etc.
- **Game Identity Board** — visual + textual representation of the game's identity.

 ## 2\. Core gameplay

 These define **what the player actually does**.

 - **Core Gameplay Loop**
- **Gameplay Loop Diagram**
- **Player Activity Flowchart**
- **Moment-to-Moment Gameplay Diagram**
- **Core Mechanics Sheet**
- **Mechanics List**
- **Mechanics Interaction Matrix**

 # The core set I'd recommend

 You **don't need all of these**. For a serious game concept, I'd build a core package of around **20 documents/diagrams**:

 1. **Game Concept Document**
2. **Game Pillars**
3. **Player Fantasy**
4. **Core Gameplay Loop**
5. **Gameplay Systems Diagram**
6. **Player Journey Map**
7. **Difficulty/Tension Curve**
8. **World Map**
9. **Level Flow Map**
10. **Enemy/Threat Matrix**
11. **Encounter Matrix**
12. **Player Ability Matrix**
13. **Combat Flow**
14. **Progression Tree**
15. **Economy/Reward Flow**
16. **Item/Equipment Matrix**
17. **Quest Flowchart**
18. **Character Relationship Map**
19. **UI/UX Flow**
20. **Game Design Bible / GDD**

 And then, depending on the genre, add specialized documents.

 ### The important distinction

 Think of the whole package as different **lenses on the same game**:

 **Game**\
 → **Vision**\
 → **Player experience**\
 → **Mechanics**\
 → **Systems**\
 → **Enemies/threats**\
 → **Levels/world**\
 → **Progression/economy**\
 → **Story/characters**\
 → **UX/UI**\
 → **Art/audio**\
 → **Technical implementation**\
 → **Balance/testing**

 If you're trying to create a **professional "game blueprint" before actually making the game**, I can also give you a **complete Game Design Blueprint template with \~50–100 sheets/diagrams, organized in the exact order you should create them**, including what columns/fields each sheet should have.
